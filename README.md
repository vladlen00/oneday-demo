# oneday-demo

Демо-копия медитации «Один день» для показа без подписки.
Живёт на https://vladlen00.github.io/oneday-demo/

Что это и чем отличается от боевого репозитория `oneday`:

- проверки доступа НЕТ вообще. Блок `irenaCheckAccess` вырезан целиком,
  а не закомментирован и не обойдён флагом;
- аудио не дублируется: берётся по абсолютной ссылке из боевого репозитория
  `https://vladlen00.github.io/oneday/oneday.mp3` (тот же origin, файл и так публичный);
- телеграм-ветки нет: `telegram-web-app.js` не подключается, демо живёт в браузере;
- кнопки «В студию» нет: она читала `irena_access_token`. Вместо неё на том же месте
  кнопка «Что ещё есть», ведущая на полный доступ. Правило на все демо: где у боевого
  был возврат, в демо стоит выход к оплате;
- внизу приглашение в приложение с меткой `?from=demo-oneday`;
- `noindex, nofollow` в шапке.

## Правила для этого репозитория

1. Демо НЕ читает и НЕ пишет ни один ключ `irena_*` в localStorage.
   Все репозитории `vladlen00.github.io` делят один origin, и запись в чужой
   ключ ломает оплаченный апп на телефоне подписчицы. Свои ключи, если
   когда-нибудь понадобятся, называть `demo_*`.
2. Ни одного обращения к Supabase: ни функций, ни `rest/v1`, ни anon-ключа.
3. Никаких Kinescope ID: в этой практике видео нет вовсе.
4. Перед каждой публикацией прогнать проверку:

   grep -c -i -e verify-access -e verify-app-token -e irena_token -e rest/v1 \
        -e glutes_schedule -e supabase -e localStorage index.html

   Все счётчики обязаны быть нулями.

## Обновление

Практика правится в боевом `oneday`. Сюда изменения переносятся руками,
с повторным прогоном проверки выше. Автоматической синхронизации нет намеренно:
она однажды перенесёт сюда и гейт, и ключи.
